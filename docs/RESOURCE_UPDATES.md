# 兔版float 内部资源更新

APK 1.0.3（内部版本5）首次加入资源更新入口。只修改运行资源，不迁移 WebView 的域名，不清理 IndexedDB、localStorage、聊天记录或备份。APK 包名 `app.ii.phone` 与原签名保持不变。

## 用户操作

先安装一次1.0.3 APK，以后在「设置 → 关于与更新 → 导入更新包」选择资源 ZIP，查看版本和说明后安装。不是把源码替换 ZIP 或 APK 导入此处。当前版本不联网自动检测/下载更新，也没有更新服务器。

页面分别显示 APK 版本与资源版本。未应用资源包时显示「内置资源」。可以恢复上一资源版本；没有上一资源版本时会恢复 APK 内置资源。资源回退不会撤销已发生的数据迁移，因此未来更新应维持数据格式兼容，并保留完整备份。

## 验证与启动回退

- 本地系统文件选择器读取 ZIP，不通过网页上传文件。包大小/解压后总量上限512MiB，单文件128MiB，最多5000个资源文件。
- 清单使用与 APK 相同的 RSA 私钥签名；客户端从已安装 APK 的签名证书读取公钥。没有硬编码私钥，也不接受任意源码 ZIP。
- 检查应用ID、精确APK内部版本、内置资源指纹、资源版本递增及所有最终文件的SHA-256。拒绝重复条目、目录穿越、未声明文件和不完整启动文件。
- 资源先写入独立暂存目录，完整校验后才切换指针，保留上一资源。新资源需在主界面完成初始化后确认启动；90秒未确认会尝试恢复上一资源。未确认时进程退出，下一次启动也会恢复。
- 回退机制只保护资源启动与切换，不承诺回滚数据结构，也不代替数据备份。已确认启动后才发生的功能性错误需手动恢复或新的资源包修复。
- 升级 APK 时回到该 APK 内置资源，旧APK对应的资源包不继续加载；当前聊天数据位置不变。

## 生成资源包（维护者）

1. 用 `npm run android:apk` 生成带内置资源指纹的同签名 APK。构建脚本顺序为 Vite、清理旧生成资源、Capacitor sync、生成 `float-bundle.json`、Gradle。
2. 发布 APK 时，永久保存对应的 `android/app/src/main/assets/float-bundle.json`。本版副本为 `mobile/baselines/1.0.3-build5.json`。后续构建会覆盖生成文件，不能用新构建的指纹替代已安装APK的基线。
3. 改网页代码，运行 `npm run android:web`，再执行示例：

```bash
python3 scripts/build-resource-update.py \
  --baseline mobile/baselines/1.0.3-build5.json \
  --dist mobile-dist --sequence 2 --id resource-002 \
  --label '资源 002' --notes-file update-notes.txt \
  --output rabbit-float-build5-resource-002.zip
```

需要 Python cryptography，以及原私人签名备份中的 `android/float-release.p12` 和 `android/signing.properties`。源码包不包含私钥。序号应大于已发布的所有资源包，回退后也不能重复导入相同或旧序号。

所有资源更新累计基于指定 APK 的内置资源，不要求依次导入中间包：ZIP 只带相对内置资源改变的文件，清单描述完整最终文件集。无需修改的图片、字体从 APK 复制，未列入新清单的旧哈希文件不会进入新版本。原生代码、插件或权限变更要发布新的 APK，并保存新基线。

## 本次验证范围

运行了实际 Java 校验/资源状态代码的JVM测试，覆盖签名/哈希错误、版本不兼容、越界路径、重复安装、暂存不激活、确认启动、未确认重启回退、超时回退、手动回退、APK升级重置，以及用户数据哨兵文件不变。浏览器验证设置组件与弹窗时使用了原生接口模拟；并非真实安卓安装/文件选择器/更新激活实机测试。

## 已知延后项

本版只修复转发聊天记录卡片对已缓存接收聊天室的刷新。群聊连续消息分组、流式预览残留保持原代码，等待用户后续确认修复。群聊气泡间距仍由该会话自定义 CSS 调整，本版不改变用户的间距设置。


## 1.0.4 在线更新

发布源固定为公开 GitHub 仓库 `lumicho111/rabbitkeeper-updatededicated`。点击「检查更新」才查询，不会自动下载安装或上传聊天、角色、密钥。使用 GitHub Releases API 的最近 30 个公开发布，跳过草稿与预发布。

附件命名必须是 `rabbit-float-build6-resource-002-verify.zip` 这种格式：build 对应 APK 的 versionCode，resource 后是递增序号。标签名称可自定，建议 `resource-002`；查找不依赖标题或标签排序。只选择当前 APK、序号大于已安装最高序号的 ZIP。回退不会降低最高序号，避免自动重新安装出问题的旧版。

1. 创建公开 Release，上传本次 `rabbit-float-build6-resource-002-verify.zip`，不要改文件名，不要解压；不要勾预发布。
2. APK 1.0.4 → 设置 → 关于与更新 → 检查更新 → 下载更新。
3. 下载完通过 APK 公钥签名、完整文件哈希、原生版本与基线兼容性校验后，再确认「安装并打开」。原有手动导入与恢复保留。
4. 本次验证包与内置功能一致，仅验证在线入口。1.0.3 对应 build5 的旧 001 包不适配 build6，新版会跳过。

后续基于 `mobile/baselines/1.0.4-build6.json` 构建资源包，序号从 3 继续，签名仍用原私有密钥。更新原生代码时需新 APK、新 nativeBuild 与新基线。此功能没有实现自动安装 APK。

网络由安卓原生连接 GitHub API 与 Release 附件，HTTPS 与 GitHub 下载重定向白名单，不经原网站服务，不需要 GitHub token。网络限流、超时、下载不完整、签名/版本不匹配均显示错误，保留当前版本；下载可重新发起，不支持断点续传。GitHub 网页能访问，不等于 API 在所有网络都能访问，需实机验证。

验证包括 Java 实际版本选择/流式下载与进度/短文件/大小限制/URL策略测试，以及原有签名校验和资源回退测试。浏览器 UI 验证使用模拟原生接口，未在真实安卓设备完成网络下载及资源激活验证。


1.0.5 / build7：修复 Capacitor JSON Integer 附件编号被 getLong 读取为空的问题。下载入口接受正整数及十进制字符串，候选输出编号字符串；仍执行重新检查和完整签名验证。此修复需要覆盖安装 APK。build7 基线为 mobile/baselines/1.0.5-build7.json，已包含资源003全部功能。
